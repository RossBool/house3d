## 新图导航地图

10/11层使用 `plans/20261014/floor10-clean.jpg`（768×1024）及 `floor11-clean.jpg`（1302×1736）作为地图底图，来自本轮用户提供的清图。图像原字节复制；`models.*.map.revision` 保存SHA-256。`structure.html` 并列显示用户标注图与全景源模型俯视图，便于核对门窗与相邻空间。

节点使用 `map_point: {u,v}`，取值0..1，基准为包含白边的完整图片。SVG采用底图原始宽高；点显示在 `u*width, v*height`，不拉伸、不再叠加上层旧米制墙线。10/11层地图点与三维相机对应；模型比例包含估算，不代表现场实测位置。图上方位不自动等于真北。出租层继续采用原有 `x/y` 和 `walls` 分支。

用户补充确认：11层餐厅下沿、会客厅入口左侧的灰色短段是到顶实体墙。地图以 `confirmed_wall` 补入该段，左侧通行口保留；原图入口提供用户标注图，避免清图漏掉补充墙段。墙高类型已确认，墙长/厚度仅按图示范围表达，非实测尺寸。

## 统一三维场景与图片导入

2026-10-14用户已将清晰度验收调整为“能看清”，并批准恢复统一三维建模。10/11层从各自唯一Blender场景输出真正的PANO/EQUIRECTANGULAR全景，不再把普通宽幅生图作为完整球面图。每张新渲染记录场景SHA、相机坐标、投影与图片SHA；两个门面的家具与材料来自同一物体。

约12.1米建筑宽与2.8米净高是估算，墙门窗位置按最新图纸及用户补充；11层无12层或上行梯；露台靠室内门洞按图保留，远端范围因图纸裁切未定义。模型不认证施工净距、设备品牌或完整露台面积。

新渲染接入须完成独立几何检查、源场景/PNG一致性检查及逐图视觉复核。网页默认视角60度，宽屏水平视角不超过100度，减少正常透视的边缘拉伸；这不能替代源图球面投影正确性。出租层图片、节点与旧地图分支维持原样。

每个房间都应有独立原图、可见限制说明及房间材质说明。旧的 `floor11-review.html` 与 `design-previews/` 保存历史修正样图，不作为本轮新图验收依据。

历史宽幅生图导入接口（不代表球面投影验收）：

```sh
node add-approved-panorama.mjs --id floor11_07 --image /absolute/path/original.png --style-preview --note '内置模型风格预览，实际1774×887，未达4K；以新户型图和实测为准，空间几何与球面接缝待核对。' --materials '独立厨房：胡桃木饰面、浅色石材台面、拉丝金属五金、玻璃移门。'
```

`--style-preview`要求完整2:1 PNG，记录 `quality_tier: STYLE_PREVIEW` 和 `approval_status: STYLE_PREVIEW_ACCEPTED`；`--draft`使该图保留草稿状态，不进入公开列表。必须提供 `--note`、`--materials`。它不认证视觉质量，也不计作高清验收。

高清入口仍要求至少3840像素宽、2:1、宽度可被4整除：

```sh
node add-approved-panorama.mjs --id floor10_11 --image /absolute/path/original.png --preview-accepted --note '预览已允许展示；几何与接缝仍待核对。' --yaw -1.5 --pitch -0.18
```

`--preview-accepted`（兼容旧别名 `--preview`）只表示允许展示高清尺寸的预览；`--approved`用于已完成视觉验收的图，脚本本身不认证视觉质量。尺寸检查不证明生成过程为原生4K。

可选 `--thumbnail /absolute/path/thumb.jpg` 复制已有缩略图；省略则显示文字房间卡片。不同图片替换同一视点须显式 `--replace`；相同哈希可重复导入。脚本原字节复制PNG，更新 `manifest.json` 与 `tour.js`，不生成、放大、拼接或重新编码图片，不提交或发布。`.import.lock`防止并发导入；异常结束后应先确认没有导入任务运行再清理该锁。

图片、缩略图和地图URL带内容revision，替换后避开旧缓存。原图查看、下载与播放器使用相同revision。仅实际导入并允许展示的节点出现在菜单及地图中；未完成组显示0/总数并禁用。

## 显示与验证

播放器读取一张完整等距柱状PNG。GPU为适配纹理上限，3840×1920图用4条原像素纹理，1774×887图用2条；都带相邻像素边缘，仅用于内存上传，不生成六面图、不拼接文件、不降采样。设备纹理上限不足时明确报错，仍保留原图入口。

```sh
node --check viewer.js
node --check add-approved-panorama.mjs
node check.mjs
node check-viewer.mjs
```

`check.mjs`核对目录42节点、清单与tour一致、PNG实际像素与哈希、新底图哈希、归一化位置、草稿隔离及高清门槛。图片导入/重建tour后运行。

`check-viewer.mjs`模拟DOM/WebGL，核对原像素复制、实际像素/材质提示、失败分支、新图原比例、节点定位/点击、独立厨房夹具、默认房间、revision缓存及出租旧地图分支。它不执行真实GPU，不替代实机视觉与地图点选验证。

实机仍需检查全景画面、拖动、缩放、全屏、地图、加载失败与接缝。单目全景环视不等于立体头显或自由行走。
